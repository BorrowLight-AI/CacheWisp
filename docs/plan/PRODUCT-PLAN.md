# CacheWisp 详细产品与实施计划

[English](PRODUCT-PLAN.en.md) | **简体中文**

版本：首版基线 v1；日期：2026-10-26。本文将已确认产品决策与工程默认值分开记录。权威任务索引见 ../TASKS.md。

## 1. 产品定义与目标

CacheWisp（轻灵）是一款免费开源的开发空间管理桌面应用。帮助开发者看清指定目录下各项目的依赖、缓存和临时构建产物占用，独立管理全局共享缓存，经过明确选择后手动清理。可选监控和 AI 建议帮助发现值得处理的变化，桌面 Wisp 提供低打扰提醒。

首发 macOS，通过 GitHub 源码及可下载安装包分发。扫描、统计与规则核心独立于 UI 和操作系统，为未来 Windows/Linux 保留复用能力。常驻资源开销优先于复杂视觉效果。

核心闭环：选择范围 → 渐进扫描 → 按项目判断占用 → 预览清理影响 → 用户确认 → 逐项目标处理 → 更新统计与历史。

## 4. 扫描与规则设计

### 4.1 范围和权限

项目扫描只能从用户明确选择的根目录开始。共享缓存必须作为独立 scope 启用。重叠根目录归一化，扫描产物拥有唯一后端 ID。权限不足、目录删除、外置盘离线及扫描取消均保留状态，不能以 0 代替未知值。

不默认全盘扫描，不跟随目录符号链接，不自动越过到其他挂载卷，不执行项目脚本或加载任意项目代码。配置解析以静态、有限读取为主；自定义路径需要落在已授权范围内。worktree 的 .git 文件、嵌套仓库、多语言工作区须有专门案例。

文件变化期间的统计可能暂不一致：显示“计算中/更新中/部分完成”和时间。后台重新核对变更范围，完成后再提交一致快照。任务可取消，取消只影响当前扫描，不抹掉上次成功结果。

### 4.2 六类生态初始覆盖矩阵

下表是待验证的规则清单，并非宣称所有目录已实现或所有内容都可清理。每条规则须记录版本、证据、排除项、恢复代价和清理策略。

| 生态        | 项目内候选                                                                         | 共享候选                                    | 必须排除/保守处理                                                                   |
| ----------- | ---------------------------------------------------------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------------------- |
| JS/TS       | 带 package.json 上下文的 node_modules；可确认框架生成的 .next/.nuxt/.svelte-kit 等 | npm 缓存、pnpm store、Yarn 缓存的可验证子项 | 不凭 dist/build 名称删除；区分符号链接、硬链接、全局 virtual store 引用；不整库盲删 |
| Python      | 有 pyvenv.cfg 与项目证据的 .venv/venv；**pycache**、pytest/mypy/ruff 工具缓存      | pip 可重建下载缓存等                        | 不按 env 名称删除；不卸载 Python/Conda 环境本体；带有用户源码的目录排除             |
| Go          | 仅能明确识别的项目工具生成物                                                       | GOCACHE、GOMODCACHE 可验证内容              | vendor 可能受版本管理，不当缓存；私有或本地独有模块保守处理                         |
| Java/Kotlin | pom.xml/Gradle 项目下可确认的 target/build/项目 .gradle                            | Gradle 缓存、Maven 仓库中的可确认可重建子项 | Maven 本地安装产物可能是唯一副本；无法证明可恢复时只统计，不整库删除                |
| Rust        | Cargo 项目/工作区的 target，静态配置中已授权的目标目录                             | Cargo 下载缓存的可验证内容                  | 不清理 rustup 工具链或 Cargo 程序安装目录；修改过的 registry 源码保守处理           |
| Swift/Xcode | Package.swift 上下文中的 .build；可映射项目的 DerivedData                          | 已明确归类的工具缓存                        | 排除 .xcarchive、签名材料、SDK、模拟器设备和用户数据；不能可靠归属时留在共享视图    |

检测优先级：强上下文证据 > 受工具定义的位置 > 目录名。Git 跟踪文件或用户源码出现在候选内时停止清理资格判定，保留只读占用。全局仓库不是天然的“全部可删除”目录。

### 4.3 项目树

Git 仓库作为常见父级，语言/工作区 manifest 定义子项目。没有 Git 的目录仍可由 manifest 识别。monorepo 父级汇总采用集合并集，父子不能简单相加。重复根、共享文件和同一产物只能在适当 scope 聚合一次。项目保护不能被选择父目录绕过。

### 4.4 统计口径

分别提供：缓存目录数、文件数、目录大小、磁盘占用估算、选中项预计释放空间。说明符号链接与硬链接的计数策略。文件数区分路径条目和去重实体，UI 默认显示可解释的路径文件数，磁盘聚合对已知物理身份去重。

已知硬链接按卷及文件身份去重；选择清理时，扫描范围外仍存在的链接意味着不能把全部分配大小认作可释放。APFS 克隆、快照、压缩、稀疏文件等可能使物理占用和释放量无法精确归属；不声称仅凭目录遍历解决全部共享块问题。

“已移入废纸篓”“已永久删除的目标大小”“卷可用空间变化”是三个不同结果。移到同卷废纸篓不会直接等于空间已释放。卷可用空间差值也不能全部归因于本应用，因为系统及其他程序可能同时写入。

技术依据：[pnpm 链接结构](https://pnpm.io/symlinked-node-modules-structure)、[Apple APFS](https://developer.apple.com/documentation/foundation/about-apple-file-system)。

## 5. 清理闭环

1. 用户选择项目或具体产物，默认不自动勾选。
2. 后端生成预览：范围、类型、数量、逻辑大小、释放估算、模式、保护及不确定项。
3. 保护项目必须先由用户解除；全局共享缓存使用独立选择与确认。
4. 确认时重新检查范围授权、规则证据、保护状态、文件身份、链接和快照时效。
5. 默认通过本机废纸篓 API 处理。外置卷使用该卷支持的系统行为；失败展示具体原因，不降级为永久删除。
6. 永久删除需要单独明确确认，不能复用“移到废纸篓”的许可。
7. 记录每个目标成功、跳过或失败，保留路径映射和时间于本地清理历史。部分失败可重试失败项，不重删成功项。
8. 更新受影响 scope 和项目汇总，监控将预期操作与外部变化合并，避免重复 AI 提醒。

后端只接收清理预览/产物 ID，不接受任意路径或模型生成命令。不自动清空整个系统废纸篓。首版恢复方式依赖系统废纸篓，不额外承诺应用内完整撤销系统。

## 6. 监控、外置盘与历史

监控由用户逐范围开启，优先系统原生事件，合并抖动与批量安装事件，限定并发和扫描 I/O。变化先标记 scope 过期，在稳定窗口后重算相关产物；不会为每条原始事件完整遍历根目录。

生命周期：打开主窗口 → 关闭主窗口后菜单栏继续 → 可单独隐藏 Wisp → 明确退出终止监控和网络任务。隐藏精灵释放其 WebView；关闭主窗口应释放或验证其不可见进程开销，重新打开恢复状态。

外置盘离线时显示“未连接”和最后扫描时间，停止该卷任务；重连验证卷身份后局部核对。相同挂载路径对应不同卷时不能误认旧数据或沿用删除预览。

历史保存聚合快照与合并事件；工程默认提议聚合历史 90 天、详细事件 30 天，可在实现时依据存储基准调整。不会把所有原始文件事件永久写入数据库。源文件最近修改信号与缓存文件最近修改信号分离，避免一次依赖安装把旧项目误判为近期开发。

## 7. AI 设计

### 7.1 连接与降级

用户配置 Base URL、API Key、模型名；首版使用 Chat Completions 兼容接口，通过连接测试确认能力，不承诺所有厂商协议一致。Key 只存系统凭证库，后端读取；本地 SQLite 不保存明文 Key。连接测试也是用户主动请求，其发送内容、调用计数应清晰。

AI 可选：缺 Key、离线、超时、服务限流或返回无效数据，均不影响扫描、监控与手动清理。云端默认 HTTPS；本地兼容服务的 HTTP 采用显式本地地址配置。远端流量由 Rust 发起，WebView 不接触密钥。

### 7.2 候选变化与脱敏

本地规则发现值得关注的变化后再调用模型。候选包含：持续增长、单项目明显增长、空间不足、长期积累的可处理产物。阈值和冷却窗口作为版本化工程配置，通过真实数据校准，不伪装成已验证的 AI 异常识别能力。

只发送项目代号、生态、产物类型、大小、文件数、变化量、聚合时间和完整性信息。真实项目名、路径、文件名、源码、依赖清单均不发送。别名映射、清理目标和授权范围留在本地。发送前对序列化后的整个 payload 做隐私测试。

模型返回结构化建议：关联事件 ID、事实依据、可能原因、建议类别、注意事项。无法由统计验证的因果关系必须表述为可能性。返回的 ID、建议类别及文本需验证，不能转成任意 HTML、路径或命令执行。

### 7.3 调用预算

默认每日最多 20 次自动分析，设置中允许用户修改，0 停用自动调用。按本机日历日计算并保存时区/UTC 时间信息；日期和时区变化的计数策略需测试。发请求前原子预留额度，自动重试也计入自动调用上限；应用重启不能重置当天计数。

不同项目变化可合并；同一问题冷却并按事件指纹去重。达到上限仍可本地提醒，不自动升级为付费手动请求。用户手动预设追问单独统计，不伪装为免费或无限额度。Token 用量仅在服务返回时展示，缺失用未知值，不按不明价格编造费用。

### 7.4 建议交互

首版提供建议卡片和“为什么增长”“清理有什么影响”等预设追问。卡片操作只能跳转到本地清理预览。没有自由聊天代理、自动删除和通用 shell 能力。

协议依据：[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

## 8. Wisp 与信息架构

主窗口：项目总览、全局缓存、变化与建议、设置。项目表格支持排序、搜索、生态/产物/修改时间筛选和父子展开。详情展示规则依据、快照时间、统计口径和清理影响。零结果、权限不足、未连接、部分完成等状态都有中英文文案。

Wisp：简洁 2D、可拖动、可隐藏、有状态提示。安静优先，普通变化合并展示，磁盘空间不足、持续增长或累计超阈值才主动冒泡；相同问题不反复打扰、不抢焦点。用户点击可查看全部变化/卡片。

动效由有限状态驱动，静止停止刷新，隐藏销毁渲染资源，遵循减少动态效果设置。先验证透明窗口资源；超预算优先减少动画、窗口与常驻进程，必要时替换精灵渲染适配器，保持主 UI 和核心接口稳定。

## 9. 技术架构

- cachewisp-core：规则、项目识别、遍历策略、统计、变化/预算策略和领域类型；不依赖 Tauri。
- Rust 桌面服务：任务调度、SQLite、事件监控、权限、卷、废纸篓/删除、Keychain、AI HTTP 和生命周期。
- Tauri IPC：类型化请求、后端 ID、错误码、进度事件，按窗口限制能力。
- React/TypeScript：系统 WebView、列表/筛选、预览确认、状态与双语；避免引入大型图表、状态和动效框架。
- SQLite：设置、根范围、项目、产物聚合、快照、事件、保护、清理批次、预算及建议；分阶段迁移，不预建全部空表。
- Wisp 适配器：独立生命周期和最小只读事件权限，不持有全量项目列表或清理 API。

前端类型与 Rust DTO 同步；后续以契约验证避免漂移。长时间扫描、数据库批量写入与网络调用不阻塞 UI 或主事件循环。锁、队列和数据库连接有界，按批次发送进度，避免百万文件产生百万次 IPC。

官方框架依据：[Tauri 进程模型](https://v2.tauri.app/concept/process-model/)、[窗口配置](https://v2.tauri.app/reference/config/)。

## 10. 验收与质量门禁

功能：六类生态每类至少覆盖真实布局、易混淆目录、受版本管理文件、权限异常和部分失败。项目/共享范围隔离、父子去重、清理重校验、保护及废纸篓失败路径必须通过。

性能：在固定设备和固定百万级 fixture 上记录冷/热扫描耗时、峰值内存、CPU、取消延迟、UI 响应与数据库增长。完整扫描秒数及扫描峰值预算尚待实测建立，不能沿用空闲预算作为扫描峰值承诺。

常驻：发布构建，关闭主窗口，开启监控、显示 Wisp，无扫描任务，预热后连续采样至少 5 分钟。合并 Rust、相关 WebView/helper 进程的内存和 CPU，记录共享内存口径、设备/系统、根数、监听数、采样脚本及原始结果。内存 ≤150 MB，平均空闲 CPU <1%。

安全与可靠性：删除仅使用临时 fixture；符号链接/硬链接/路径替换/外置盘重连/保护父子穿透/数据库重启/AI 并发预算/隐私 payload 进入回归测试。

易用性：中英双语、系统语言切换、键盘导航、焦点恢复、减少动态效果、无 Key 与离线完整本地流程。详见 ../VALIDATION.md。

## 11. 工程默认值与待实测事项
