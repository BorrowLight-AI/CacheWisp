## 推荐执行顺序

1. 完成 CW-001 后，优先 CW-002 → CW-003 → CW-004，建立真实端到端扫描路径。
2. 尽早启动 CW-021 的独立 Wisp 窗口/静止资源验证，避免把常驻预算风险留到最后。
3. 规则任务 CW-005～CW-009 可按开发生态逐条实施；不要在同一 PR 横向重写所有模块。
4. CW-010 提供统计语义之后，进入 CW-011 → CW-012 清理；先基于临时 fixture 验证，再开放用户操作。
5. CW-014 → CW-015 → CW-016 构建快照、监控和生命周期。
6. CW-017 → CW-018 → CW-019 → CW-020 完成凭证、脱敏、预算与建议。CW-022 集成 Wisp 提醒。
7. CW-023 控制历史/索引增长，CW-024 在完整发布构建上验收；最后 CW-025 交付。

这里的独立任务不代表自动创建并行 Agent；每次选任务按依赖顺序推进。

## 三项优先技术风险

| 风险                      | 早期验证                                      | 失败后的处理                                |
| ------------------------- | --------------------------------------------- | ------------------------------------------- |
| 百万文件统计过慢/内存过高 | 有界遍历与队列，硬链接 fixture，冷/热扫描数据 | 降低并发、调整索引/批次与归并，保持统计口径 |
| 废纸篓与清理竞态          | 临时根、外置卷/权限失败、目标替换、父子选择   | 停止对应目标，记录错误；禁止永久删除降级    |
| Wisp 常驻超预算           | 单窗口 release 原型，静止/隐藏/重建采样       | 减少动画/窗口，替换精灵渲染适配器           |

## 进度管理

任务按纵向用户能力拆分，状态与依赖见 ../TASKS.md。每个完成任务补充运行记录和适用限制。首版未通过资源门禁时继续保留预发布标记。签名证书、公开仓库权限属于最终发布依赖，不阻止本地开发和构建。
